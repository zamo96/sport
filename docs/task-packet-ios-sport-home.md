Дата: 21 сентября 2026. Основание: пользователь одобрил `product-first-value-and-return-2026-09-20.md` и поручил реализацию в дизайне iOS.

## Scope и критерии приемки

Первый законченный этап — нативный SwiftUI интерфейс поверх существующих API: четыре намерения (партнер, компания, личные тренировки, центры); персональная Главная с релевантным действием; ближайший план и неделя личной активности. Выбор можно менять. Существующие аккаунты не проходят заново обязательную анкету.

- Первый запуск объясняет четыре сценария, сохраняет выбор при прохождении действующего onboarding и регистрации.
- Главная открывает реальные экраны игроков, групповых поисков, визитов и центров. Возврат и нижнее меню работают.
- Намерение — локальное предпочтение, не новое поле профиля/API; смена не стирает планы и данные.
- История владельца включает completed визиты без фото и played игры, с учетом групповых дублей. Прошедшая дата не означает состоявшееся занятие.
- Пусто, загрузка и ошибка различаются. Каталог доступен независимо от наполнения недели. Гостевые ограничения сохраняются.
- Сохраняются восстановление сессии, обязательные город/спорт и переходы из уведомлений/deep links.
- Тексты RU/EN, доступные действия, малый экран и увеличенный шрифт.
- Нет вымышленных событий, обязательной цели недели, автоматической брони или публикации.

Прямое создание прошедшего визита, новая социальная сеть/«мой круг», новые рекомендации и backend-агрегация вне этапа. Учесть факт существующего визита можно в текущем сценарии. История новой Главной относится к загруженным данным и выбранной неделе, не обещает полную пожизненную статистику.

## Архитектура и владельцы

Product Analyst зафиксировал acceptance; Solution Architect проверяет контракт; два Mobile исполнителя работают по разным файлам; QA проверяет правила учета, границы доступа и регрессии.

- Onboarding Mobile: `Core/UserIntent.swift`, `Services/UserIntentStore.swift`, `Views/AuthView.swift`, при необходимости отдельный extension и минимальные lifecycle hooks `App/AppModel.swift`.
- Home Mobile: `Views/SportHomeView.swift`, `Core/SportHomeWeek.swift`, при необходимости отдельный loader.
- Orchestrator: только интеграция в `Views/ContentView.swift`, включение новых файлов в Xcode, документация и общие проверки.
- QA: отдельные проверки `ios/Tests`, review стабильного diff. Не владеет основной реализацией.

Источник истины: существующие серверные `PersonalActivity.status` и `MatchGameRequest.outcome`. Новая сводка — отображение этих состояний. Ранжирование, eligibility и переходы игровых статусов не меняются. Контракты API и база не меняются.

Рабочее дерево содержит ранее внесенные несохраненные изменения в auth, media, widgets и клиентах. Их не откатывать и не включать в описание этой задачи как новые результаты.

## Домены

Затрагивается iOS представление профиля/намерения, спорта, географии, расписания, игровых предложений/лобби, личных визитов и центров. Чат, непрочитанное и уведомления сохраняют существующую логику; проверяется только достижимость навигации. Matching, no-show/reliability, premium, web, Android и backend не меняются.

## Проверки

Обязательны Debug simulator build, релевантные iOS проверки onboarding/session, узкие тесты новой сводки и хранения намерений, визуальная проверка и четыре маршрута в симуляторе. Npm lint/test/build и Prisma не требуются при отсутствии изменений web/backend/schema.

## Результат реализации

- Новый первый экран объясняет четыре сценария; выбор необязателен. Обязательная анкета спорта и города сохранена. Предпочтение хранится локально отдельно для гостя и каждого аккаунта; уже сохраненный выбор аккаунта имеет приоритет при входе.
- Главная содержит одно действие по выбранной цели, ближайший план, прошедший план для отметки результата и текущую спортивную неделю. Цель можно менять. Для каталога без активности неделя не навязывается.
- Партнер открывает игроков; компания — действующий поиск с фильтром групп; визит — выбор центра и существующую форму личного плана; центры — обычный каталог и карточки клубов. Футбол с одним свободным местом остается групповым сценарием.
- После входа гостя продолжается визит в выбранный им центр, включая выбранный спорт. Отмена входа и выход из аккаунта очищают отложенный переход; он потребляется однократно после закрытия авторизации.
- Сводка учитывает только личные и участвующие игры пользователя, различает планы и подтвержденные результаты, убирает групповые дубли. Фото не требуется. Ошибки API не превращаются в пустую историю; ответы прежней сессии не попадают в новый аккаунт.
- На accessibility-размерах шрифта выбор цели, календарь с полными датами и легенда располагаются вертикально. Обычная раскладка сохраняет семь дней в строку.

Новые файлы приложения: `Core/UserIntent.swift`, `Services/UserIntentStore.swift`, `App/AppModel+UserIntent.swift`, `Core/SportHomeWeek.swift`, `Views/SportHomeView.swift`. Интеграция: `AuthView`, `ContentView`, `CourtsView`, фильтр `DiscoverView`, узкие lifecycle hooks `AppModel`, доступность существующего `Sport.isTeamSport` и ссылки Xcode project. Изменения в файлах с предыдущей работой ограничены этими участками.

## Ограничения и остаточные риски

Проверка интерфейса выполнена на отдельном симуляторе с тестовыми данными. Физический iPhone, отдельный малый экран, полный VoiceOver-проход и английская локаль визуально не проверены. Реальная доставка писем/Apple Sign In и серверная бронь не проверялись; создание личного плана не является бронированием клуба. В продуктивную среду ничего не публиковалось.

Предпочтение цели не синхронизируется между устройствами. История ограничена доступными записями существующих API и текущей неделей, без заявлений о пожизненной статистике. Прямое создание прошедшего визита и социальный «свой круг» остаются отдельными продуктовыми этапами. Эффект на возвращаемость — продуктовая гипотеза; он требует наблюдения за реальным использованием после выпуска.
