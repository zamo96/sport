# Операционная аналитика и конверсия в первую игру

## Запрос и результат

Удобная аналитика приложения в операционной панели и постоянный журнал действий для поиска потерь конверсии. Пользователь подтвердил приоритет: **регистрация → первая игра**.

## Организация работы

- Orchestrator: интеграция, документация, обязательные проверки, завершение.
- Product Analyst: требования, границы метрик, критерии приёмки.
- Solution Architect: источник истины, контракт данных и распределение модулей.
- Backend: аналитические агрегаты и регистрация серверных фактов.
- Frontend: экран аналитики и сбор просмотров web.
- QA: независимая проверка готового изменения и рисков.

Существующие незакоммиченные изменения пользователя сохраняются. Снимок исходного состояния находится в `.artifacts/analytics/initial-status.txt`.

## Критерии приёмки

1. Аналитика доступна только администратору; существующая операционная панель и модерация остаются доступны.
2. Есть выбор периода, показатели активности, воронка регистрации в первую игру и понятные знаменатели/потери.
3. Первая игра означает `GameRequest.outcome = played`, а не мэтч, согласование или истечение времени. Подпись уточняет, что игра отмечена в приложении.
4. Журнал сохраняет успешные ключевые действия; серверные факты нельзя отправить через клиентский API.
5. Доступны фильтры журнала и выгрузка для последующего анализа; данные и запросы имеют разумные ограничения.
6. Ошибка вспомогательного сбора не ломает пользовательское действие.
7. Пустая база, отсутствие событий, нулевые знаменатели и неполная история явно обработаны. Исторический DAU не вычисляется из текущего `lastActiveAt`.
8. Проверены lint, test, build, доступ и пользовательский экран; ограничения записаны.

## Домены и границы

| Домен | Влияние |
| --- | --- |
| Профиль | Измерение регистрации и завершения профиля |
| Спорт и уровень | Только контекст действий, правила не меняются |
| Геолокация и районы | Правила не меняются; точные координаты не нужны в журнале |
| Доступность | Правила и интервалы не меняются |
| Предложения игр | Измерение создания, принятия и отметки сыгранной игры |
| Поиски и лобби | Измерение поиска и отклика |
| Рекомендации | Измерение просмотров/свайпов; рейтинг не меняется |
| Чат | Счётчики действий без содержимого сообщений |
| Уведомления | Существующие push-события доступны для анализа |
| Отмены/no-show/reliability | Статусы учитываются при трактовке игры; правила не меняются |
| Premium | Оплата и доступы не меняются, доход не вычисляется без источника платежей |

Серверные события распространяются на web и iOS через общие API. Отдельное изменение SwiftUI не входит в первоначальный объём. Анонимная рекламная атрибуция, A/B-платформа и реконструкция отсутствующей истории не входят в объём.

## Реализовано

- `/admin/analytics`: период 7/30/90 календарных дней UTC, новые и активные игроки, конверсия регистрации в первую игру, сыгранные игры, последовательная воронка и потери, дневная динамика, распределение событий, журнал с постраничной выдачей.
- Прямая конверсия считается по данным игр независимо от промежуточных событий. Наблюдаемая воронка требует последовательности событий одного игрока. Эти показатели и их ограничения подписаны отдельно.
- Журнал фильтруется по игроку и действию; фильтры сохраняются при смене периода. Из существующего поиска игроков можно перейти в карточку и открыть «Историю действий». CSV использует те же фильтры и ограничен 10 000 строками событий, с явным предупреждением при усечении.
- Серверный журнал: регистрация email/Apple, первое заполнение профиля, свайп, мэтч при взаимном свайпе, создание поиска, отклик, предложение, согласование, отметка сыгранной игры, отправка сообщения. Подключены общие API web/iOS и web server action подтверждения регулярной игры.
- Web: открытие приложения, просмотр подбора, вход в онбординг; только фиксированные названия экранов. Есть ограничение частоты и защита от повторного вызова React effects.
- Запись после сохранения основного действия, до отправки уведомлений. Для ключевых этапов стабильный ключ события устраняет повторы и конкурирующие дубли без миграции.
- API событий принимает только разрешённые клиентские типы и ограниченный контекст, проверяет сессию и лимит 16 КБ. Страница и CSV проверяют администратора до чтения данных.

Полные определения и контракт: [admin-analytics-design.md](admin-analytics-design.md).

## Ограничения и запуск

1. Код выложен на production 6 сентября 2026: [release-20260906-analytics.md](release-20260906-analytics.md). История отсутствовавших событий не восстанавливается. Новая миграция не потребовалась; используется существующая таблица `UserEvent` и настройка администраторов `ADMIN_EMAIL`/`ADMIN_EMAILS`.
2. Сбор вспомогательный: при сбое журнала основное действие сохраняется, аналитика может недосчитаться событий. Это не журнал с гарантией доставки.
3. Когорта открытая: недавно зарегистрированные игроки имели меньше времени дойти до игры. Сравнение периодов не заменяет фиксированную конверсию за одинаковое число дней жизни аккаунта.
4. «Сыграли» означает отметку в приложении; споры и исправления результатов пересчитывают историческую конверсию. Принятое групповое приглашение без собственного результата наследует сыгранный результат корневой игры; явный `not_played` исключается.
5. Полная аналитика просмотров iOS, анонимные посещения, атрибуция рекламы, удержание по фиксированным когортам, выручка и A/B-эксперименты — отдельное развитие. `match_created` отражает только путь взаимных свайпов.
6. При значительном росте данных стоит добавить предварительно рассчитанные показатели и согласовать срок хранения. Удаление аккаунта удаляет его события через существующее каскадное удаление.
