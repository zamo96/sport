# iOS: мультивыбор целей без изменения основного входа

## Запрос и границы

Пользователь уточнил дизайн: цели должны поддерживать мультивыбор; прежний первый экран onboarding нужно вернуть; переключатель «Играть в компании» в поисках не нужен; цели не должны закрывать доступ к «Игрокам», «Поискам» и «Ближайшим играм».

## Критерии приемки

- Корневой экран основной вкладки — прежний Discover с тремя действующими вкладками. Начало работы, повторное открытие Главной и прямые ссылки не требуют выбора целей.
- «Моя неделя и цели» открывается только по желанию через кнопку календаря. Нативная кнопка назад возвращает к выбранной вкладке Discover. Нижнее меню и прямые ссылки позволяют выйти из дополнительного раздела.
- Цели — набор из 0–4 значений. Каждая включается и выключается независимо; нажатие не закрывает редактор. Кнопка «Готово» завершает выбор. Для каждой выбранной цели доступно действие в существующем приложении.
- Локальный выбор хранится отдельно для гостя и аккаунтов. Старое одиночное значение переносится без потери. Явный пустой набор аккаунта не заменяется гостевым выбором.
- Прежние оформление, hero и основные кнопки первого экрана onboarding восстановлены точечно. Требования анкеты и действующая логика авторизации сохраняются. Вымышленный счетчик пользователей не возвращается.
- В поисках нет ни видимого переключателя компании, ни скрытого ограничения выдачи по целям.
- Предыдущие исправления личных визитов после входа, учета фактических занятий и границ сессии сохраняются.

## Архитектура и владельцы

Product Analyst / QA фиксирует acceptance и независимо проверяет результат. Architect / Mobile владеет `UserIntentStore`, `AppModel+UserIntent`, восстановлением `AuthView` и тестами хранения. Второй Mobile владеет только `SportHomeView`. Orchestrator делает интеграцию `ContentView`/`DiscoverView` и документацию. QA заменяет ставшие ненужными тесты фильтра групп на проверки маршрутов.

Контракт AppModel: `selectedUserIntents: Set<UserIntent>`, `setUserIntents(_:)`, `toggleUserIntent(_:)`. Хранилище использует массив raw values в прежних scoped keys и поддерживает чтение старой строки. Набор целей не влияет на доменные фильтры и ранжирование.

Затронут только iOS: локальное предпочтение профиля, первый экран, представление игровых поисков и навигация. Спортивные уровни, геолокация, доступность, жизненный цикл запросов/игр, matching, чат, unread, push, no-show/reliability и premium не изменяются. API, база, web и Android не изменяются. Существующие сторонние несохраненные изменения сохраняются.

## Проверка

Нужны актуальные тесты хранения/миграции, обязательного onboarding, lifecycle, загрузки недели и маршрутов; Debug simulator build; визуальная проверка первого экрана, прямого доступа к трем вкладкам, отсутствия переключателя и мультивыбора/снятия всех целей. Тесты неизмененных правил недели и продолжения визитов повторять без новой причины не требуется. Npm/Prisma проверки неприменимы: соответствующие поверхности не меняются.

## Результат и проверка

Все критерии реализованы. В `ContentView` корень снова `DiscoverView`, а неделя — необязательный destination. Кнопка календаря в `DiscoverView` открывает его явно; выбор целей не влияет на выдачу. В `AuthView` восстановлены прежние hero, сменяющийся заголовок и кнопки. `SportHomeView` показывает действия всех выбранных целей в стабильном порядке; изменение отметки не закрывает редактор.

- **147 актуальных проверок PASS:** хранение/миграция 31, обязательный onboarding 36, lifecycle 27, продолжение визита 14, навигация 24, загрузка недели 15. Неизмененные правила недели ранее прошли 34 проверки; повторный прогон не требовался.
- Новые `ios/Tests/HomeNavigationTests.swift` и runner проверяют реальные методы маршрутизации и структуру корневого экрана. Устаревшие `HomeGroupDiscoveryTests.swift` и runner удалены вместе с отмененным фильтром. Тесты хранения обновлены под наборы и миграцию.
- **Обычная Debug simulator build PASS**, arm64 и x86_64. Команда: `xcodebuild -project ios/TennisSearchIOS.xcodeproj -scheme TennisSearchIOS -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath /tmp/tennis-sport-home-build CODE_SIGNING_ALLOWED=NO build`. Лог: `/tmp/tennis-goals-correction-build.log`.
- **Mock simulator build PASS**, лог `/tmp/tennis-goals-correction-mock-build.log`. Настройки проекта на mock не переключались.
- **Runtime PASS** на отдельном iPhone 17 Pro / iOS 26.3: прежний intro, вход сразу в игроков, прямое переключение всех трех вкладок, отсутствие группового переключателя, необязательное открытие недели, миграция прежней цели, выбор всех четырех целей без закрытия редактора, снятие всех отметок, сохранение пустого набора при повторном открытии, два параллельных действия, возврат назад с сохранением вкладки «Поиски». Действие «Посмотреть игры» возвращает в полную выдачу, включая одиночный теннис с одной вакансией; цель компании не скрывает его.
- Независимое QA review, `git diff --check` и валидация файла Xcode project: **PASS**.

## Ограничения

Предпочтения локальные, без синхронизации между устройствами. Интерфейс проверен в симуляторе с mock-данными; физический iPhone, малый экран, реальная авторизация и живой backend в этот прогон не входили. Публикации приложения не было. Существующие несохраненные изменения других задач не откатывались.
