# Изменение статуса заполнения профиля администратором

## Запрос и границы

В карточке игрока администратор может перевести профиль из черновика в заполненный и обратно. Управление отдельное от редактирования полей: смена статуса должна работать и на пустой анкете, не заполняя данные автоматически.

## Контракт и ответственность

- Источник истины: существующий `User.onboardingCompleted`.
- Existing `PATCH /api/admin/players/:id/profile`: `{ expectedUpdatedAt, profile: { onboardingCompleted: true | false } }`. Поле необязательное; остальные запросы совместимы.
- Backend: только boolean в whitelist админского профиля и регрессионные тесты. Существующие транзакция, optimistic lock и `AdminAuditLog.PROFILE_UPDATED` сохраняют изменение вместе с актором и значениями до/после.
- Frontend: отдельный выбор статуса и сохранение, обновление бейджа/истории, блокировка конкурирующих сохранений и защита несохранённых правок формы.
- QA: независимая проверка UI и backend после обязательных проверок. Orchestrator: интеграция, изолированная проверка и выкладка поверх актуального production.

## Критерии приёмки

1. Работают оба перехода, в том числе отправка `false`.
2. Пустой черновик меняет только статус; поля имени, города, спорта и доступности не меняются.
3. Статус сохраняется после повторного открытия, бейдж и история показывают актуальное состояние.
4. Неавторизованные и обычные пользователи не имеют доступа к административному изменению. Устаревшая версия получает 409 без записи/аудита.
5. Нет фиктивного `profile_completed` в журнале пользовательских событий: административное действие остаётся административным.
6. `isVerified`, `accountStatus`, сессии, уведомления и игровые договорённости не меняются.
7. Несохранённая основная форма не теряется из-за отдельного сохранения статуса.

## Домены

Изменяется профиль. Существующие правила используют признак завершённого профиля для допуска в подбор и направления пользователя в онбординг. Формулы ранжирования не меняются. Спорт/уровень, география, доступность, поиски/предложения, чат/unread, push, отмены/no-show/reliability и premium не изменяются. Аналитика текущего количества заполненных профилей отражает новое значение; пользовательская воронка не получает искусственного события.

Миграция и изменения нативных клиентов не требуются. Чужие изменения рабочего дерева сохраняются.

## Ограничения

Администратор может отметить заполненным профиль с пустыми полями; данные не заполняются автоматически. Существующие ограничения активности/верификации и подбора сохраняются. Возврат в черновик влияет на прохождение онбординга и участие в подборе, но не деактивирует аккаунт и не отменяет договорённости. Записи реальных пользователей на production для проверки не изменяются.
