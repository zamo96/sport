# iOS: личные визиты с медиа, содержимое дня и понятный первый вход

## Запрос и результат

Расширить личный визит до полноценной карточки с фото и видео. При выборе даты в «Моей неделе» показывать события и результаты этого дня. Убрать цели из недели, спрашивать их необязательно и с мультивыбором в онбординге; после входа объяснять возможности через реальные действия.

## Критерии приемки

- Исходная главная страница онбординга сохранена. До обязательных шагов доступен необязательный выбор 0…4 сценариев, с явным пропуском. Он не меняет поиск, уровни спорта, доступные разделы или авторизацию.
- После входа доступны «Игроки», «Поиски», «Ближайшие игры». Компактная закрываемая подсказка с четырьмя действиями помогает начать; выбранные сценарии идут первыми. Точные переходы из уведомления/сохраненного визита имеют приоритет. Закрытие подсказки хранится отдельно для каждого аккаунта.
- В неделе нет блока «Мои цели». Выбранный местный день показывает состоявшиеся занятия, планы, записи без результата и отмены с честными статусами. Счетчик завершенных занятий не меняет правил. Переключение дня не запускает загрузку.
- Карточка личного визита открывает подробности. Владелец может сохранить результат без вложений, добавить фото/видео к завершенному визиту и изменить комментарий, сохранив остальные вложения. Ошибка загрузки не очищает сохраненный отчет и не отмечает план состоявшимся.
- Просмотр медиа доступен из визита, недели и личной истории. Видео запускается вручную и останавливается при уходе/смене страницы. Старые записи только с фото продолжают работать.
- Сохраняются проверки сессии/владельца, partial-load и ошибки источников, крупный текст и Reduce Motion.

## Владельцы

- Product Analyst / QA: требования, регрессии навигации и приватности, независимая проверка итогового diff.
- Architect / Backend: media contract, хранение/валидация/сериализация, совместимые iOS модели и repository, доменные тесты.
- Mobile: карточка/подробности/редактор визита, галерея, содержимое дня недели, отображение медиа в истории; узкая вставка подсказки в Discover по контракту root.
- Root: исходный онбординг и интеграция необязательных целей, сохранение/показ подсказки, навигационная интеграция, Xcode ссылки и общая проверка.

## Домены и границы

Затронуты личный профиль/визит, медиаданные визита, отображение жизненного цикла игр и визитов, локальные предпочтения первого использования и iOS навигация. Ранжирование, sport/level eligibility, геопоиск, слоты доступности, матчинг, chat/unread, push, no-show/reliability и premium не меняются. Нет автоматической публикации медиа, редизайна web/Android или автоматического завершения прошедших планов. Старые незакоммиченные изменения других задач сохраняются.

## Остаточные ограничения и выпуск

- Полный сценарий добавления нового фото/видео через системный PhotosPicker остается непроверенным из-за ограничения CUA. Фактический production-метод сохранения и upload-ошибки покрыты 26 проверками с управляемым транспортом; перед выпуском нужен ручной smoke-тест выбора и загрузки новых файлов на устройстве.
- Runtime выполняется с mock-данными в симуляторе. Физическое устройство, реальные аккаунты, загрузка на рабочий backend и production-хранилище этим прогоном не проверены.
- Перед выкладкой нового backend необходимо применить SQL добавления `PersonalActivity.videoUrls`; успешная генерация Prisma client не заменяет применение изменения базы.
- Существующая доступность файлов по известному публичному URL сохраняется. Доступ владельца проверяется для списков и мутаций, но это не защищенное чтение самого файла.
- Сервер проверяет поддерживаемый контейнер/MIME и размер видео, без гарантии длительности или воспроизводимости каждого кодека. Парные отчеты в этой задаче остаются только с фото.

## Технический контракт (Architect, 2026-09-21)

- Источник факта личного занятия — `PersonalActivity.status == completed`; для игры — accepted/approved + outcome played. Время окончания позволяет предложить отметку результата, но не создает его. Сохраненный результат нельзя переоткрыть или перенести; отмененный визит не получает отчет. У личного визита при отсутствующей длительности проверка окончания использует серверные 60 минут, а записанная длительность в истории остается неизвестной.
- Additive schema: `PersonalActivity.videoUrls Json @default("[]")`; deploy SQL `prisma/deploy/20260921_personal_activity_videos.sql` применяется до нового backend. Фото и прежняя relation не меняются. GET/PATCH возвращают дополнительный массив `videoUrls`, старые клиенты его игнорируют; iOS декодирует отсутствующий ключ как пустой массив.
- PATCH `photoUrls?` / `videoUrls?`: отсутствие каждого поля сохраняет вложения этого типа; `[]` удаляет только этот тип. Совместный лимит — 8 вложений с учетом уже сохраненного второго массива. Редактирование комментария не требует повторной отправки файлов. Новые video URLs должны принадлежать текущему владельцу и точному визиту; они не становятся медиа профиля/игры.
- POST `/uploads/personal-activities/:id`: существующий ответ `{photoUrl}` для изображения, дополнительный `{videoUrl}` для видео. Фото — существующий лимит 20 MiB; видео — MP4/MOV до 60 MiB, проверка MIME и контейнера. Длительность/кодек сервером не гарантируются; не показываем неподтвержденный лимит по секундам. Порядок показа — фото по прежнему position, затем видео по порядку массива; произвольное перемешивание типов не обещается.
- Граница доступа сохраняет существующую систему: списки и мутации доступны владельцу, отчет не публикуется. Сам известный URL файла остается публично доступен, как у текущих фото/парных отчетов. Это остаточный риск; защищенное чтение медиа и миграция существующих public URLs в эту задачу не входят. Не называем файлы полностью приватными.
- iOS: `PersonalActivity.videoUrls:[String]`, `PersonalActivityUpdateDraft.videoUrls:[String]? = nil`, `uploadPersonalActivityVideo(activityId:data:fileName:mimeType:) async throws -> String`. `ProfileWorkoutHistoryItem.videoPaths:[String] = []` передает видео только личного занятия. Парные отчеты остаются photo-only.
- `SportHomeWeek.events` содержит все доступные канонические события текущей локальной недели; `events(on:calendar:)` выбирает весь день. Состояния planned/pending/needsReview/completed/canceled/notPlayed; completedCount не включает планы, пропуски и отмены. У дня есть отдельные reviewCount/otherCount. Дедупликация по root и приоритет корневой записи происходят до проверки статуса, сортировка date→id стабильна. UI не повторяет eligibility; медиа завершенного события находятся по canonical ID в `ProfileWorkoutHistoryItem`.
- Необязательный onboarding хранится локальным состоянием AuthView без нового обязательного AuthStep. Цели сохраняют существующее различие отсутствия настройки и явного `[]`, guest adoption только при успешном входе. Discover принимает компактный блок стартовых действий внутрь своего scroll; учет закрытия отдельный по аккаунтам и не меняет маршруты уведомлений/продолжения визита.
